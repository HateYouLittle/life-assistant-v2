# Life Assistant v2 重构实施计划

**地点**：在空工作区 `C:\WorkSpace\new-life` 从零搭建 v2（旧仓库 HateYouLittle/life-assistant 仅作参考与数据迁移来源，不做修改）。

## 一、进程拓扑（方案 A：单守护进程）

- `src/daemon.ts` 唯一常驻进程：MCP over Streamable HTTP（Hono 挂载官方 SDK 的 `StreamableHTTPServerTransport`，默认 127.0.0.1:3080）+ cron/tick 调度 + outbox 投递 + `/api/status` + 单文件静态状态页。
- `src/stdio.ts` 兼容壳（~100 行）：Hermes 若只支持 stdio 注册（`hermes mcp add --command node --args dist/stdio.js`），壳把 JSON-RPC 转发到 daemon 的 HTTP 端点；daemon 未运行时输出明确错误。若 Hermes 原生支持 HTTP MCP 可跳过。
- **单写者原则**：全部 SQLite 写入收敛到 daemon → 删除 lease 抢占、stale-claim takeover、fencing、"第二个 scheduler 退出码 1" 等跨进程防护；保留 WAL + 单事务 outbox。
- 部署：单个 systemd unit。

## 二、数据归属模型（简化为两域）

- **Profile 私有**：schedules / occurrences / notifications / deliveries / settings（quiet hours 等）
- **全局共享**：节假日日历、位置与天气缓存、**账本（所有 Profile 均可读写，无角色/成员/授权层）**

## 三、schema v1（SQLite STRICT + WAL）

- `meta`（schema 版本/节假日元数据）、`profiles`、`settings(profile_id, key, value_json)`（quiet hours、push route；secret 仍在 env）
- `ledgers(id, name, archived_at)` —— 全局资源，无 profile 归属字段
- `expenses(id, ledger_id, amount_cents, category, note, spent_on, created_by_profile, created_at)` —— 只记支出；`created_by_profile` 仅用于展示"谁记的"，不参与授权
- `schedules` + `occurrences`（两层，公历/农历/重复/工作日-节假日频率）
- `notifications` + `deliveries`（outbox，保留有界重试与静默时段）
- `cn_holiday_days` / `cn_holiday_years`
- 迁移：`npm run import:v1 -- --data-dir <旧DATA_DIR>` 一次性导入旧库的 schedules/账目/节假日/设置；旧库只读打开，拒绝覆盖已初始化的目标库；旧共享账本的角色/成员信息不迁移。

## 四、MCP 工具面（46 → ≤12）

- `weather({view: current|forecast|alert})` 与 `air_quality()` —— **统一走 QWeather**（实时/7 日预报/预警/国标 AQI，含生活数据所需的城市定位缓存），不再引入 Open-Meteo，无多源回退；单轮 provider 失败按"该轮不产出"处理
- `holiday({view: next|month|is_workday})`
- `schedule({action: add|list|update|complete|delete|upcoming})`
- `ledger({action: create|list|rename|archive})` + `expense({action: add|list|summary})` —— 任何 Profile 均可调用，服务层不做权限校验；`expense list/summary` 支持 `by: profile` 维度
- `notify({action: pull|quiet_hours|cancel})`
- 备份走 `npm run db:backup`（VACUUM INTO），无 assistant 工具

## 五、通知渲染（微信/企业微信，Markdown 表格）

- 统一 IR：`{title, table{columns, rows}, notes[]}`，渲染为 Markdown 表格；不支持表格时降级为"键: 值"逐行。
- 固定模板：每日简报（项目|内容：天气/温度区间/预警/AQI/提示）、日程提醒（事项|时间|重复）、记账回执与月报（分类|金额|占比+合计行+记账人）、节假日提示（日期|安排）。
- 记账回执/月报按全局事件处理：fan-out 物化到每个配置了推送路由的 Profile（沿用 publishGlobal 语义，Profile 内去重）。
- 投递协议不变：deliver-only 回环 webhook、HMAC-SHA256 V2（`timestamp.body`）、`X-Request-ID`、10s 超时、有界重试（非 2xx ≤5 次、传输不确定 ≤3 次后 fallback，退避 1m/5m/15m/1h 封顶）、at-least-once 并如实声明。
- quiet hours（跨午夜）与 `notify.pull` 兜底保留；snooze/cancel 并入 notify 的 action。

## 六、自研 recurrence 引擎（替代 rrule）

- `src/core/recurrence.ts` 纯函数：daily/weekly/monthly/yearly（含农历月日）× interval + workday/holiday 过滤（查 `cn_holiday_days`，缺数据暂停并标记）+ until/count；漏触发只补最近一次。
- 节假日导入沿用旧仓库的校验规则（节日完整性、调休仅周末、全年 20–45 天等）。
- 全部调度固定 Asia/Shanghai 单时区 → DST 相关复杂度整体消失。

## 七、依赖与工程面

- 保留：@modelcontextprotocol/sdk、hono、@hono/node-server、zod、luxon、lunar-javascript、node-cron、Biome、node:test、node:sqlite。
- 移除：rrule、Open-Meteo、TianAPI/JUHE、React/Vite/Tailwind 整条前端链。
- strict TS，Biome `noExplicitAny` 按报错而非警告；GitHub Actions CI（typecheck+lint+test）。
- 测试目标约 120–200 用例：recurrence 表驱动、outbox 重试/静默、导入迁移、渲染快照、registry 契约、账本并发写入（两 Profile 交替写同一账本）。
- `skill/SKILL.md` 重写为精简版（≤1500 词，匹配新工具面）。

## 八、分阶段落地（每阶段可验证）

1. 骨架：daemon + Hono + MCP HTTP + 模块注册表 + config + schema v1 + db:backup
2. recurrence 引擎 + schedule 模块 + 节假日抓取/校验
3. 通知：outbox + 表格渲染器 + webhook 投递 + quiet hours + pull
4. QWeather 接入：weather/air_quality + 07:00 确定性每日简报（单边失败不发送）
5. 记账：全局多账本 + 支出 + 每月 1 号月报（全局 fan-out）
6. stdio 壳 + 状态页 + import:v1 + SKILL.md + README（Hermes 注册、微信 webhook 配置）
7. 收尾：CI、部署文档（单 systemd unit）、对照旧仓库功能验收

每阶段 DoD：`tsc --noEmit` 0 错、`biome lint` 0 错、`node --test` 全绿、无新增 any。

## 九、明确砍掉清单

**自动化模块整体**（含条件 DSL 与白名单动作引擎）、油价模块（含 TianAPI/JUHE）、Open-Meteo 多源回退、共享记账的角色/成员/权限体系（账本全局可编辑）、React 仪表盘工具链（换单文件状态页）、生活指数、export/import MCP 工具、snooze/cancel 独立工具、legacy 表与 v4–v8 迁移机器、跨进程 lease/fencing、DST 处理、强提醒完整语义（降级为"到点重发一次"）。

**风险与对策**：Hermes 的 MCP 传输能力在阶段 1 先做 stdio 壳的技术验证（spike）；webhook 协议字段名在实现时对照旧仓库源码逐一核对，保证 Gateway 侧无感切换；QWeather 为单点数据源，免费档配额用尽时各轮查询明确报错不猜测。
